## 已从实车确认

- `yhs_can_control` 实际 launch 文件是 `yhs_can_control.launch`。
- 运行时链路是 `/move_base -> /cmd_vel -> /velocity_smoother -> /smoother_cmd_vel -> /yhs_can_control_node -> can0`。
- `/chassis_info_fb` 类型是 `yhs_msgs/FwChassisInfoFb`，包含 `ctrl_fb`、`io_fb`、`bms_flag_fb`、`bms_fb`。
- `move_base` action 与 `/move_base_simple/goal` 都存在。
- `/move_base/cancel` 已做 C1 只读安全闭环验证。
- `/recharge` 和 `/dis_recharge` 的 service type 已从代码确认，但默认 `yhs_nav.launch` 未启动 `recharge_node`。
- 3D/NDT 模式下存在 `map -> base_link` TF，`odom -> base_link` TF 不存在是预期，因为 `/yhs_can_control/tfUsed=false`。

## 仍待确认

- Rviz 多点导航插件发布哪些 topic/service/action。
- 录制路径文件保存在哪里，格式是什么。
- `recharge_node` 的实车启动、充电桩坐标、安全前提。
- 不同车体/不同 `chassis_type` 下 `/chassis_info_fb` 字段是否一致。
- C2 小位移测试：需要电量更高、操作员确认解锁流程、现场安全条件满足。

## 进入大系统后的接口候选

| PDDL 动作 | 车端实现候选 | 备注 |
|---|---|---|
| `navigate(ugv, waypoint)` | `move_base` action | 主入口 |
| `patrol_route(ugv, route)` | 原厂多点/录制路径能力或自研 waypoint executor | 需确认插件接口 |
| `stop(ugv)` | cancel move_base + zero `/smoother_cmd_vel` | 高优先级 |
| `dock(ugv, charger)` | `/recharge` | 有充电桩才启用 |
| `undock(ugv)` | `/dis_recharge` | 有充电桩才启用 |
| `report_pose(ugv)` | `/odom` / map pose | 需确认定位坐标系 |
