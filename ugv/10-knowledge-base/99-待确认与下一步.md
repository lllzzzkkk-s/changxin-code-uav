# 99 - 待确认与下一步

## 连接车端后先确认

```bash
hostname
whoami
echo "$ROS_DISTRO"
echo "$ROS_MASTER_URI"
ls -la ~/catkin_ws/src
```

## 运行只读探测

把本仓库脚本复制到车端后执行：

```bash
bash probe_ugv_readonly.sh --workspace-dir ~/catkin_ws --pack-source
```

如果是在车端已经有 `changxin-code` 仓库：

```bash
cd ~/changxin-code
bash ugv/01-scripts/probe_ugv_readonly.sh --workspace-dir ~/catkin_ws --pack-source
```

把输出目录中的 `summary.txt`、`05_code_index.txt`、`06_launch_files.txt`、`07_yaml_configs.txt`、运行时 topic 文件贴回。

## 必须从实机代码确认的问题

- `yhs_can_control` 实际 launch 文件名是 `.launch` 还是 `.launch.py`。
- `/smoother_cmd_vel` 的订阅者、消息类型、限速逻辑。
- `/chassis_info_fb` 的消息类型与字段。
- `move_base` action 是否标准 `/move_base`，是否被原厂插件包装。
- Rviz 多点导航插件发布了哪些 topic/service/action。
- 录制路径文件保存在哪里，格式是什么。
- `/recharge` 和 `/dis_recharge` 的 service type 与参数。
- `yhs_nav_param.yaml` 中全局/局部规划器、代价地图、速度限制、障碍源配置。
- 3D 导航时 NDT/AMCL/LIO-SAM 的实际定位链路。
- 车端是否运行 ROS2 相机节点，是否有 ROS1/ROS2 bridge。

## 进入大系统后的接口候选

| PDDL 动作 | 车端实现候选 | 备注 |
|---|---|---|
| `navigate(ugv, waypoint)` | `move_base` action | 主入口 |
| `patrol_route(ugv, route)` | 原厂多点/录制路径能力或自研 waypoint executor | 需确认插件接口 |
| `stop(ugv)` | cancel move_base + zero `/smoother_cmd_vel` | 高优先级 |
| `dock(ugv, charger)` | `/recharge` | 有充电桩才启用 |
| `undock(ugv)` | `/dis_recharge` | 有充电桩才启用 |
| `report_pose(ugv)` | `/odom` / map pose | 需确认定位坐标系 |
